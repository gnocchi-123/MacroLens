# 한국투자증권 Open API 도입 계획

2026-10-18 당시 결정: **KIS 실제 연결과 키 입력은 사용자 준비 후 진행**한다. 지금은 연결 준비와 오프라인 검증을 계획하며, 키가 없어도 기존 FRED·샘플·이력·재현은 정상 동작해야 한다. KIS는 기본 비활성이고 명시적으로 선택한 가격 수집 작업에서만 인증한다. 미설정 가격은 미수집/보류로 표시하며 합성 가격을 실제 가격으로 대체하지 않는다.

## 1. 데이터 역할과 범위

| 출처 | 역할 | 이번 도입 범위 |
| --- | --- | --- |
| FRED·ALFRED | INDPRO·UNRATE·CPIAUCSL·DGS10와 과거 vintage | 기존 M3 수집·시점·표준화 규칙 유지 |
| KIS | ETF 시장 가격·거래량·권리·종목 식별 | 일별 가격·수정주가 옵션·배당/분할 대조부터 구현 |
| ETF 운용사 공식 자료 | 상품 식별·배당·분할 교차검수 | 기존 State Street 대조원 활용, 현재 수정 여부와 주당 기준 확인 |
| 거래소 달력 | 휴장·조기 종료·정규장 시각 | 기존 달력과 공식 근거 활용, API 날짜의 시장/시간대 대조 |

KIS 도입은 확정했으나 데이터 적격성은 미확정이다. 실시간 호가·분봉·뉴스·환율·업종 순위는 후속 후보다.
현재 단계는 조회 전용이다. API 주문, 자동매매, 실제 계좌 잔고 연결, 유료 가입을 이 문서로 활성화하지 않는다.
프로젝트 자체의 모의 운용과 증권사 모의투자 서버는 별개다. 시세 조회를 위해 실전 서버를 사용하더라도 실제 주문이 필요한 것은 아니다.

2026-10-18 공식 가이드·공식 Python 예제를 확인했다. API 기능 존재와 실제 종목별 역사 범위를 구별한다.

| 공식 기능 | 확인된 목적 | 추가로 확인할 것 |

권리 정보의 '예정'은 변경될 수 있다. 날짜 필드 이름만 보고 배당락일이라고 단정하지 않는다.
해외 ETF는 해외주식 인터페이스에서 종목별 지원을 확인한다. 국내 ETF 구성종목 API가 미국 ETF 보유종목을 제공한다고 가정하지 않는다.
KIS 업종 코드를 M3의 11개 섹터 분류와 자동으로 동일시하지 않는다.

이는 제공을 보장하는 날짜가 아니다. 종목별 최초/최종 실제 관측일·행 수·권리 범위를 표로 남긴다.

2022~2023년 관점 변화는 기존 연구 가설로 보존하며 표본이나 기간을 성과에 맞춰 바꾸지 않는다.

## 4. 가격·권리 입력 계약

현재 `price_audit`의 Yahoo형 CSV와 옵션 검증은 KIS 계약이 아니다. 기존 기능을 유지하고 공급자별 어댑터를 추가한다.
KIS 응답을 yfinance 응답이라고 표시하거나 존재하지 않는 `Adj Close`를 복사 생성해 검사를 통과시키지 않는다.

다음은 **구현할 내부 필드 설계**이며 KIS 응답의 정확한 필드명을 확정한 것이 아니다.

| 종류 | 저장할 의미 |
| --- | --- |
| 식별 | provider=kis, 티커, 공급자 상품번호·거래소 코드, 통화, 시장 시간대 |
| 가격 | 현지 거래일, OHLCV, 수정 옵션, 조정 범위/기준일, 정규장 여부, 공급자 갱신 시각(제공될 때) |
| 권리 | 종류, 사건 ID(제공될 때), 배당락일·기준일·지급일 또는 분할 거래일, 금액·통화·주당 기준·신주/구주 비율, 예정/확정, 수정 이력 |
| 요청 | API 경로, 비밀을 제외한 파라미터, 요청 범위·페이지/연속키, 서버 종류, 요청/응답 시각 |
| 증거 | 원본 파일 해시, 어댑터/정의 버전, Git 커밋, 수집 ID, 검수 ID, 공식 대조 근거 |

상장 이전·휴장·가격 누락·빈 응답·API 실패·권리 없음은 서로 다른 상태다.
페이지가 반복되면 무한 재시도를 중단하고 불완전 수집으로 기록한다. 날짜 진행 여부·중복 행·충돌 값·누락 거래일을 검사한다.
빈 권리 응답은 `unknown`으로 두고, 범위와 제공 계약을 확인한 경우만 '사건 없음'으로 판정한다.
결측 자동 보간·전일 가격 매매·설명 없는 분할 수리·공급자 혼합으로 자료 관문을 우회하지 않는다.

## 5. 총수익률과 체결가격

KIS의 수정주가 옵션만으로 현금배당 재투자 총수익률을 보장하지 않는다.
비조정, 분할만 조정, 배당 포함 조정, 조정 범위 미확인을 구분해 검수한다.

- 원장 방식: 비조정 시장가격·분할 수량 변화·배당 권리/현금·지급/재투자 시점을 명시한다.
- 조정계열 방식: 조정 산식·배당/분할 범위가 확인된 계열만 사용하고 배당을 다시 더하지 않는다.
- 자본이득 분배, 특별배당, 분할 전 배당의 주당 기준을 확인한다. 빈 금액은 0으로 대체하지 않는다.
- 두 방식 중 채택할 정의를 실제 사건 대조 뒤 성과 계산 전에 동결한다. 공급자의 조정계열을 실제 지급일 현금 원장이라고 표현하지 않는다.
- 연구 체결은 판단 이후 가능한 미국 정규장 종가를 기준으로 설계한다. 과거 조정가격의 절대값을 당시 체결가격으로 사용하지 않는다.
- 수익률 정의·만기·구간·통계·비용의 미확정 제안은 [M4 검증 설계](m4_validation_design.md)를 따른다.

`strict_point_in_time=false` 유지: 가격 공급원 변경은 FRED vintage의 날짜 단위 한계를 해결하지 않는다.
후향적으로 수집한 권리 수정 정보는 결과 정산에 쓸 수 있지만 당시 알려진 거래 신호로 소급 사용하지 않는다.

## 6. 인증·비용·보존

공식 이용 절차는 계좌/ID 연결, Open API 신청, App Key/App Secret 발급을 포함한다.
키 발급 여부·환경은 사용자 쪽에서 확인하고 키 자체를 대화에 요구하지 않는다.
환경변수는 `KIS_APP_KEY`, `KIS_APP_SECRET`이며 별도 키 설정 파일·`.env` 자동 로딩은 사용하지 않는다. 서버는 `--env real` 또는 `--env demo`로 반드시 선택한다. 토큰·앱시크릿·계좌번호·인증 헤더가 Git·보고서·로그에 남지 않게 한다.
허용된 시장 응답만 원본으로 저장하고 인증 응답과 헤더는 별도 보호 캐시에 둔다.

- 토큰 만료 전 재사용, 인증 요청의 별도 제한, 동시 갱신 중복 방지.
- API별 호출 제한·429/서비스 오류·타임아웃을 분류하고 제한된 재시도/백오프·중단 후 재개.
- 실전/모의 서버의 지원 차이·시세 지연·계정 이용 자격을 기록. 모의 서버 성공이 실제 시세 품질을 보증하지 않음.
- 무료 전체 역사·호출 무제한·실시간 무료를 전제하지 않음. 실제 이용 조건·호출 한도·요금은 구현 시 공식 자료와 계정으로 확인.
- 초기 추가비용 0원 목표 유지. 유료 전환은 필요·가격·대안을 제시한 뒤 별도 결정.
- 원자료의 개인 보존·가공·재배포 범위를 확인. 현재처럼 원자료는 Git 제외 경로, 공개 저장소에는 코드·설계·검수 요약만 보관.

저장 설계 후보: `data/kis/<수집 ID>/` 아래 비밀 제외 요청 명세·시장 응답·정규화 결과·해시·완료/실패 상태.
`data/price_audit/<검수 ID>/`에 검수·공식 대조와 출처 수집 ID를 연결한다. 디렉터리명은 구현 전 설계이며 아직 산출물이 없다.
후속 재수집은 새 ID와 버전으로 저장하고 원본·이전 판단을 덮어쓰지 않는다. 오프라인 재검수는 저장한 원본만 사용한다.

## 7. M5~M8 연결 및 완료 판단

- M5: 보고서에 가격 기준일·수집 시각·출처·수정주가 정의·배당/분할·누락 상태와 검수 ID 표시. 기존 거시 점수 변화 원인과 가격 변화를 구분.
- M6: 장기 보존·복구·토큰 캐시·호출 제한·휴장/지연·중복 실행 처리를 검증한 뒤 주간 자동 수집.
- M7: 고정 모델로 실제 새 주간 판단과 모의 보유 평가 기록. 증권사 주문 연동은 필요하지 않음.
- M8: 자료 공백·비용·검증 결과를 보고 환율·실시간·개인 계좌 등 확장 여부 결정.

수집기 완료는 비밀 누출 방지·실패 처리·실제 3종 응답 보존·오프라인 재검수 증거가 있어야 한다.
자료 적격성 완료는 조정 의미·권리·거래일 대조와 공통 기간 근거가 추가로 필요하다.
이 둘이 완료되어도 점수의 예측력·투자 효용 검증 완료가 아니다.

## 8. 다음 구현 요청

3종 적격성 통과 전 12종 확대나 전략 결과 계산을 완료로 표시하지 않는다.

## 10. 나중에 연결하는 방식 (구현 요구사항)

1. 기본값은 KIS 비활성. 전역 초기화/import/기존 weekly 실행에서 키를 읽거나 토큰을 요청하지 않는다.
2. `KIS_APP_KEY`, `KIS_APP_SECRET`을 환경변수에서 읽는다. Codespaces Secrets 반영 후 실행할 수 있다. 이번 별도 환경에는 키가 없어 실제 인증은 확인하지 않았다.
3. 실전/모의 환경은 가격 수집의 별도 설정으로 명시하고 토큰 캐시를 환경별 분리한다. 키 값·토큰을 모델 설정/해시에 넣지 않는다.
4. 키가 없으면 기존 FRED/sample/history/compare/replay/report는 계속 작동한다. 사용자가 KIS 전용 작업을 요청했을 때만 설정 누락을 안내하고 해당 작업을 중단한다.
5. 저장된 KIS 원본의 오프라인 검수에는 키가 필요하지 않아야 한다. 테스트는 모의 응답을 쓰고 네트워크를 차단한 상태에서도 실행 가능하게 한다.
6. 구현이 끝나면 README에 키 등록 위치, Codespace 재시작/환경 반영 방법, 연결 점검 명령, 비활성화 방법, 정상·오류 출력을 적는다. 키나 토큰 자체를 출력하는 확인 명령은 쓰지 않는다.
7. 실제 연결 시 XLC·XLK·SPY부터 검수한다. 키가 없는 현재를 이유로 M1~M3를 막거나 M4 실제 검증 완료로 표시하지 않는다.

[M1~M3 호환성과 Codex 전달 내용](codex_kis_handoff.md)을 함께 따른다.

API 한 페이지의 범위가 더 넓으면 원문 전체를 보존하고 해당 구간만 검수한다.
`collect`는 해시 검증 및 현재 검수 코드로 재판정한 **같은 서버·거래소의 probe**가 필요하다.
`can_collect=true`는 전체 증거 수집 가능 표시이고, 자료 적격성·권리 완전성 승인이 아니다.
전체 목표는 2020-06-01~2026-09-30, 평가 후보 시작 2021-06-07 그대로다.

유료 가입·접근 제한 우회·새 가입은 하지 않았다. 이미 키를 설정한 사용자는 본인

이 확인은 모의 테스트로 대체되지 않으며 자동 보고서에도 제한으로 남는다.

  실제 자료 3종 결과 검토 전 12개 확대나 백테스트로 진행하지 않는다.
  `strict_point_in_time=false`, M3 동결 모델, R-001 후속 연구를 유지한다.

해외 상품정보 URL·CTPF1702R은 여전히 공식 예제에 있다. 특정 TR 폐지·계정 권한·서버 장애로
원인을 확정하지 않으며, 에러 문구를 추정해 코드에 넣지 않는다.

**공식적으로 문서화된 두 조회를 함께 쓰는 선택지**를 추가했다. 자동 우회/묵시적 fallback은 없다.

| 식별 선택 | 공식 계약 | 대조 |
| --- | --- | --- |
| `overseas` (기존 기본값) | 해외 search-info / CTPF1702R | 기존 거래소·통화 검사 그대로 |
| `basic-quote` | 공통 상품기본조회 `/uapi/domestic-stock/v1/quotations/search-info` / CTPF1604R | 반환 pdno가 요청 티커와 일치하고 prdt_type_cd가 529(AMS) 등 요청 유형과 같아야 함 |
| 위 선택의 두 번째 조회 | 해외 현재가상세 `/uapi/overseas-price/v1/quotations/price-detail` / HHDFS76200200 | curr=USD 및 rsym=D+요청 거래소+티커가 일치해야 함 |

공통 상품기본조회는 이름/경로가 domestic-stock이어도 공식 예제에 AAPL/512 및 미국 아멕스/529가
명시되어 있다. 근거는 `examples_llm/domestic_stock/search_info/{search_info,chk_search_info}.py`.
현재가상세의 AUTH/EXCD/SYMB, curr/rsym/etyp_nm 정의는
`examples_llm/overseas_stock/price_detail/{price_detail,chk_price_detail}.py`에서 확인했다.
외부 라이브러리는 조사 참고만 했으며 새 의존성으로 설치하거나 실행하지 않았다.

두 조회가 모두 일치해야 가격 수집용 식별 검사를 통과한다. 조회 실패·다른 상품·유형·통화는
계속 차단한다. 현재 응답의 last/open 등은 원본 증거로만 보관하고 과거 가격 행에 넣지 않는다.
현재 상품정보는 과거 상장/분류 이력을 보증하지 않으며 총수익 적격성을 승인하지 않는다.
해당 응답의 원문·명시적 API 경로·TR ID·수집 시각·해시와 identity_source를 보존한다.

probe에 `--identity-source basic-quote`를 지정한다. collect는 저장 probe의 식별 경로를 그대로
따르며 명시적으로 다른 경로를 지정하면 거부한다. 이전 기록에서 identity_source가 없으면
기존 overseas 계약으로 읽는다. 이전 실패 기록을 새 경로 성공으로 소급 변경하지 않는다.
`recheck`는 두 원본으로 네트워크 없이 재검수한다.

ICE 0행은 여전히 unknown이다. 소량 조회의 ICE 검색일은 배당락일이 아닌 주로 발표일이므로
12월 배당이 있어도 그 요청에서 나오지 않을 가능성과 공급자 범위를 구별해야 한다.
두 식별 응답과 가격 검사가 통과하면 `can_collect=true`가 될 수 있지만 권리 대조가 남은 `held`는
유지한다. 이 표시는 **전체 증거 수집 가능**이며 12개 확대·총수익 평가 승인이 아니다.

## 13. 대체 경로도 같은 오류일 때의 최소 진단

사용자 실제 보고서에서 basic-info와 price-detail도 모두 HTTP 500 / EGW02004였다.
12절 대체 경로의 실제 성공은 확인되지 않았으며 문제 해결로 표시하지 않는다.
기존 GET 전달 경로는 두 API에도 동일하게 적용된다. 전체 probe 재실행 대신
`python -m macrolens.kis diagnose --env real`로 SPY price-detail을 한 번만 요청한다.

이 명령은 오류 코드와 함께 KIS의 msg1을 **정제한 설명**을 받기 위한 것이다.
전체 오류 JSON은 출력·저장하지 않고, 키/토큰 반사나 제어문자가 있으면 설명을 생략한다.
주소와 자유 영문/숫자 식별값은 마스킹하며 일반 API 용어와 허용된 TR ID만 남긴다.
POST 인증 오류는 기존처럼 본문을 읽지 않는다. 기존 probe/collect의 코드-only 오류 기록은 유지한다.
진단 결과는 개인 Git 제외 data/kis_diagnostics의 새 폴더에 저장하고, 성공한 시장 응답만 원문 보존한다.
GET 최대 1회(15초), 인증은 캐시가 없을 때 별도 필요할 수 있다. 재시도·권한 우회·서버 전환 없음.

해당 설명을 실제로 확인하기 전 코드가 뜻하는 근본 원인이나 해결을 확정하지 않는다.
진단 성공도 상품/가격/권리 적격성을 승인하지 않으며 가격 수집 관문을 해제하지 않는다.

## 14. 실제 실전 키 확인과 날짜 기반 가격 페이지 이동 (2026-10-31)

사용자가 전달한 진단 msg1은 “실전투자 도메인은 모의투자 앱키로 호출하실 수 없습니다.”였다.
실전용 한 쌍으로 교체한 뒤 diagnose `20261031T110730Z-4b237f29328d` 성공,
probe `20261031T110803Z-5727f5301451`은 held이지만 can_collect=true였다.
이는 사용자 실행 증거이며 이 환경의 직접 API 검증은 아니다.

후속 collect `20261031T110924Z-3131c70d88d1`은 세 상품/두 옵션 모두 repeated_price_page,
중복 포함 198행(2026-05-11~09-30), 결측 1493으로 중단됐다. 권리/ICE는 각각
XLC 26/21, XLK 27/22, SPY 26/21이다. 사건 수는 역사 완전성·금액 검증을 뜻하지 않는다.
원본 요청 헤더/페이지는 이 환경에 없으며, 사용자 보고서와 코드의 반복 경로를 대조했다.

공식 예제의 [dailyprice 구현](https://github.com/koreainvestment/open-trading-api/blob/3a9be59a3ed8745720dc3aa9d584bdf3b7830362/examples_llm/overseas_stock/dailyprice/dailyprice.py)은
BYMD를 조회기준일자로 정의하며 M/F일 때 같은 날짜와 tr_cont=N으로 재귀 호출한다.
해당 예제를 따랐던 기존 수집기에서 실측 반복을 막았지만 더 과거로 이동하지 못했다.
공식 예제만으로 기준일 포함 여부와 이 경로의 실제 페이지 이동을 보증할 수 없다.

가격만 `date-boundary-v1` 정책으로 바꾼다. 응답의 연속조회 헤더는 원본 메타데이터에 보존하되,
매번 가장 오래된 반환 날짜를 다음 BYMD로 삼고 tr_cont는 빈 값인 새 날짜 조회를 한다.
첫 요청은 목표 마지막 날짜+1일, 최종 구간은 양끝 포함 필터링한다.
기준일을 포함하는 공급자는 경계 행을 한 번 더 반환할 수 있다. 해당 행이 이전 페이지 마지막
행과 **전체 필드가 동일**하고 새 페이지가 더 오래된 날짜까지 진행할 때만 정규화에서 한 번 집계한다.
제외하는 공급자는 바로 이전 날짜부터 이어진다. 이 방식은 포함 여부를 추정하여 하루를 빼지 않는다.
경계 값 충돌·둘 이상의 겹침·페이지 내부 중복·날짜 정체·페이지 반복은 원문을 보존하고 중단한다.
페이지 상한 100·호출 간격·요청 제한은 유지하며, 권리 조회의 연속키 방식은 변경하지 않는다.

새 manifest에 price_pagination을 기록하고 audit가 원본 요청/행에서 같은 규칙을 다시 검증한다.
정규화 내역은 automatic_corrections에 날짜·옵션·양쪽 원본 이름과 raw_modified=false를 남긴다.
가격 값 자체는 보정하지 않는다. 이전 archive에는 이 규칙을 소급 적용하지 않는다.
기존 중복 기록은 계속 보류이며, 새 collect가 새로운 폴더에 수집한다.
M3 동결 모델·의존성·권리 의미·strict_point_in_time=false·R-001 후속 상태는 유지한다.
실제 재수집은 아직 미실시이며, 날짜 전진이 확인되어도 달력 기준 누락과 양끝 날짜를 따로 검사한다.

## 15. 전체 가격 확보 후 XLC 오류 행의 오프라인 진단 (2026-10-31)

사용자의 날짜 이동 수정 후 보고서에서 XLK/SPY는 각각 두 옵션 모두 1592행, XLC는 1591행이며
기간은 2020-06-01~2026-09-30이다. XLC만 날짜/숫자/OHLC 검사 오류와 결측 1일이 남았다.
새 실행 ID와 원문은 미전달이므로 구체적인 날짜/값은 추정하지 않는다. 14절 실패 실행과 구별한다.

전체 API 재수집 전에 `recheck`에서 원본을 재사용하여 상세 진단을 생성한다.
기존 숫자·유한성·양수 가격·음수 거래량·고가/저가 검사를 그대로 수행하며, 실패하면
사유 코드, 날짜(해석 가능한 경우), MODP, 원본 파일, output2의 1부터 시작하는 행 번호,
관측 숫자 필드를 audit.json 최상위 price_row_errors에 추가한다.
숫자 필드는 짧은 숫자 형태만 보고서에 옮기고 자유 문자열/객체는 표시하지 않는다.
오류 원문은 페이지에 보존하며, 행 번호는 경계 중복 정규화 전 원본 위치를 가리킨다.
report.md에는 각 옵션의 결측 날짜 및 상품별 오류 최대 10건, 전체는 audit.json에 남긴다.

상품 판정·유효 가격 행·기존 issues는 변경하지 않는다. 새 진단은 최상위 필드여서 이전 audit와
상품 판정이 같으면 기존 matched 비교는 유지된다. 새 진단의 일치와 원본 비변경도 합성 테스트한다.
진단 없이 held를 해제하거나, 고가/저가를 종가로 치환하거나, 0/결측을 전일 값으로 보간하지 않는다.
이 추가 기능은 조회 권한·원자료 품질·배당 조정 정의를 승인하지 않으며 네트워크 요청을 하지 않는다.
