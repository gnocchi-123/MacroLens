### 0.1 AI 역할에 대한 설명

사용자가 ChatGPT에 코드 제작 프롬프트, 오류 설명, 코드 검토를 요청하는 것은 **개발 과정의 지원**이다. 완성된 프로그램이 실행될 때마다 AI를 호출해야 한다는 뜻이 아니다.

프로그램 안의 **선택적인 AI 설명 기능**은 확정된 계산 결과를 읽기 쉬운 문장으로 설명하는 역할이다. 예를 들어 “점수 4점 상승 중 성장 요인이 3점 기여했다”는 사실을 풀어서 설명할 수 있다. 계산이나 검증을 AI에게 맡기지 않아도 주간 보고서는 완성된다.

첫 버전은 추가 AI API 호출 없이 JSON 결과와 템플릿으로 보고서를 만든다. 사용자는 필요할 때 생성된 보고서를 ChatGPT에 제공해 해설을 요청할 수 있다. 향후 API 자동 설명을 도입한다면 요금·상품 포함 범위를 공식 자료로 별도 확인한다. 현재 구독만으로 모든 자동 호출이 제공된다고 전제하지 않는다.

### 0.2 점수 모델의 출처와 한계

“경기 변화가 기업 이익·금리·신용에 영향을 주고 섹터별 반응이 다를 수 있다”는 관점은 경기순환 기반 섹터 투자와 연결된다. Fidelity의 경기순환 설명은 이런 접근의 참고 사례다. 그러나 그 자료가 MacroLens의 산식이나 계수를 검증해 주는 것은 아니다. [1]

기존 첨부 문서에는 특정 논문에서 산식을 그대로 가져왔다는 근거가 없다. **60개월, z값 ±3 제한, 민감도 -2~+2, 기준점 50, 누락 허용 80%는 자체 설계한 시작값**으로 취급한다. 이미 추정·검증된 계수처럼 안내해서는 안 된다.

경제적으로 그럴듯한 설명과 수익률 예측력은 다르다. 금리 상승은 할인율 부담이 될 수도 있지만 성장 기대의 반영일 수도 있다. 시장 가격에 이미 반영된 정보일 수도 있다. 따라서 계수에는 반대 설명을 함께 남기고, 거시 정보를 사용하지 않는 전략과 비교해 실제 추가 가치를 확인한다.

### 0.3 주간 판단과 주간 거래

매주 거래 여부를 검토하는 방향을 반영한다. 다만 판단 주기, 전망 기간, 거래 주기는 별개다. 향후 3개월을 평가하는 점수를 매주 갱신하고 매주 거래 여부를 판단할 수 있다.

월별 거시지표는 발표가 없는 주에는 새로운 정보가 없을 수 있다. 반면 주별 고용 자료나 금리에는 변화가 있을 수 있다. 목표 비중이 바뀌지 않아도 가격 변화로 실제 보유 비중이 달라질 수 있으므로, 점수 변화와 비중 이탈을 함께 본다. 보유 비중이 목표에서 벗어나는 현상은 일반적인 리밸런싱의 이유이기도 하다. [2]

“매주 거래할 수 있음”을 “매주 반드시 거래함”으로 바꾸지 않는다. 매주 조정, 월간 조정, 조건부 주간 조정을 동일한 데이터·점수·비용 조건에서 비교한다. 구체적인 실험 규칙은 5절에 명시한다.

### 0.4 스트레스 테스트의 우선순위

프로젝트의 중심은 거시 분석과 섹터 점수의 유효성 확인이다. 복잡한 충격 시뮬레이터를 먼저 만드는 것은 이 목적에 비해 과하다.

다만 평균 성과가 좋아도 특정 하락기에 이익을 모두 잃거나, 작은 거래비용 증가만으로 성과가 사라진다면 실제 활용 근거가 약하다. 따라서 실제 충격기의 손실, 거래비용 증가, 체결·데이터 지연, 일부 설정 변경에 대한 최소 점검은 유지한다.

가상 금리·물가 충격으로 손실을 정교하게 추정하는 기능은 후순위다. 가상 스트레스는 미래 사건 예측과 다르며, 연준의 공식 설명도 두 개념을 구분한다. 이는 개념상의 참고일 뿐 은행 규제용 시험을 이 프로젝트에 적용한다는 뜻은 아니다. [3]

### 0.5 이전 보고서와의 연결

전주 보고서의 문장을 AI가 기억하는 방식보다 당시 입력·점수·판단을 구조화해 저장하는 방식이 정확하다. 보고서는 그 기록에서 생성한다.

“무엇이 얼마나 바뀌었는가”, “새 발표 때문인가, 과거 통계 수정 때문인가”, “상승 흐름이 지속되었는가”, “지난 판단이 이후 성과와 연결되었는가”를 구분해 보여준다. 모델을 바꾼 주에는 경제 상황 변화와 모델 변경 효과도 구분한다. 세부 설계는 6절에 둔다.

## 1 프로젝트 방향과 확정 조건

### 1.1 목표

미국 거시경제 자료로 섹터별 환경을 점수화하고, 높은 점수의 섹터가 이후 상대적으로 좋은 성과를 보이는지 검증한다. 핵심 산출물은 **점수·검증 프로그램과 이전 판단을 추적하는 주간 보고서**다.

SPY보다 높은 장기 성과는 투자 적용 단계의 목표다. 경제 설명의 타당성, 섹터 선택 능력, 실제 투자 성과는 각각 평가한다. 현재 환경만 설명한 기록을 미래 경제 전망의 적중 사례로 세지 않는다.

### 1.2 사용자 확정 조건

| 항목 | 확정 내용 |
| --- | --- |
| 시장 | 미국 분석 시장으로 제한. 한국·글로벌 시장 확장은 현재 범위에 포함하지 않음. |
| 개발 경험 | 간단한 코드 작성 가능. Python 경험은 제한적이므로 단계별 설명 제공. |
| 협업 방식 | 코드 작성 지원과 함께 재사용할 코드 제작 프롬프트도 제공. |
| 기본 비용 | 현재 ChatGPT 이용 금액을 고정 비용으로 봄. 초기 추가 지출은 0원을 목표로 설계. |
| 추가 예산 | 프로그램의 효과가 확인되면 월 1만~2만 원 추가 지출 의향. 즉시 유료 가입 승인으로 보지 않음. |

추가 예산은 데이터·개발 환경·자동 실행·저장·선택적 AI API를 합한 운영비로 관리하는 것을 기본안으로 둔다. 실제 투자금·매매 비용·세금은 별도로 성과에 반영한다. 유료 기능 도입 시 전체 월 추가비용과 기대 효용을 먼저 제시한다.

### 1.3 이번 개정의 설계 기본값

Python, GitHub Codespaces 개발 방향을 유지한다. 미국 11개 섹터, 달러 기준, 향후 3개월 주평가·1개월 및 6개월 보조 평가를 제안한다. 한국어 Markdown·HTML 보고서와 파일 직접 확인을 기본으로 한다. 이 세부값들은 사용자 확정 사항과 구분한다.

포함: 수집, 시점별 조회, 점수와 기여도, 이력 비교, 검증, 모의 운용, 최소 그래프.

후속: 대시보드, 개인 포트폴리오, 개별주, 선택적 AI 해설, 복잡한 위험 시나리오.

초기 제외: 증권사 주문 연동, 자동 매매, 뉴스·AI 문장에 따른 임의 점수 변경, 복잡한 머신러닝.

## 2 기술 구성과 프로그램 구조

### 2.1 단계적으로 도입하는 기술

| 목적 | 선택안 | 도입 시점 |
| --- | --- | --- |
| 핵심 언어 | Python, 구현 시 지원·호환성을 확인해 버전 고정 | 처음 |
| 환경 관리 | uv, pyproject.toml, uv.lock | 처음 |
| 수집·계산 | httpx, pandas, NumPy | 처음 |
| 작은 결과 저장 | JSON, CSV, Markdown | 처음 |
| 누적 원본·분석 조회 | Parquet, 필요 시 DuckDB | 이력 규모가 커질 때 |
| 설정 | YAML, 필요 시 Pydantic | 계수·입력 검증 단계 |
| 보고서·그래프 | Jinja2, Matplotlib | 주간 보고서 단계 |
| 통계 | SciPy, 필요 시 statsmodels | 과거 검증 단계 |
| 품질 관리 | pytest, Ruff | 핵심 로직 구현부터 |

표는 기술 선택안이며 모든 패키지를 첫날 설치해야 한다는 뜻은 아니다. 구현 때 공식 문서와 환경을 확인하고 잠금 파일로 재현 가능한 버전을 고정한다. 무료 사용량을 무제한으로 가정하지 않는다.

### 2.2 모듈 책임

1. `ingest`: 원본 수집, 수집 시각·출처 저장.
2. `snapshots`: 기준 시각에 이용 가능한 자료 선택.
3. `features`: 지표 변환, 과거 기준 표준화, 요인 생성.
4. `scoring`: 섹터 점수와 기여도 계산.
5. `history`: 이전 실행 연결, 차이·추세·변화 원인 계산.
6. `evaluation`: 예측 평가, 백테스트, 거래 빈도 비교, 모의 운용.
7. `reporting`: 확정 결과에서 표·그래프·문장 생성.

보고서 작성 단계에서 점수나 비중을 임의 수정하지 않는다. AI가 없어도 전체 과정이 동작해야 한다. 나중에 AI 해설을 붙일 경우 입력 출처·생성 버전·숫자 검증을 기록하고 실패 시 템플릿으로 대체한다.

## 3 데이터 수집과 저장 설계

### 3.1 첫 개발의 네 지표

| 축 | 지표 후보 | 첫 실험의 변환 제안 | 양수 요인의 뜻 |
| --- | --- | --- | --- |
| 성장 | 산업생산 INDPRO | 전년 대비 증가율 | 과거 기준보다 성장률이 높음 |
| 고용 | 실업률 UNRATE | 3개월 차이에 -1을 곱함 | 과거 기준보다 고용 변화가 개선됨 |
| 물가 | 소비자물가 CPIAUCSL | 전년 대비 상승률 | 과거 기준보다 물가 상승률이 높음 |
| 금리 | 10년 국채금리 DGS10 | 최신 이용 가능 값과 28일 전까지의 최신 이용 가능 값의 차이 | 과거 기준보다 금리 상승 폭이 큼 |

위 변환은 연구용 기본안이다. 표준화 이후의 양수는 절대적인 경기 호황·금리 상승을 반드시 의미하지 않는다. 원래 값과 표준화 값을 나란히 보여준다. 예를 들어 성장률이 음수여도 과거 평균보다 높으면 성장 요인은 양수가 될 수 있다.

ICSA, 근원 PCE, 2년 금리, 실질금리, 금융여건 지수는 기본 파이프라인 검증 후 추가한다. 금융여건 지수에 들어 있는 금리·신용 정보를 다른 축과 중복 가중하는지 확인한다. 단위·계절조정·빈도·변환은 공식 메타데이터로 확인한다.

### 3.2 당시 알 수 있었던 데이터

FRED와 ALFRED를 우선 검토한다. FRED의 실시간 기간 기능은 과거 특정 시점에 알려진 정보를 다루는 데 사용한다. 정확한 장중 발표 시각은 별도로 관리한다. [4]

- `observation_date`: 어느 월·주·날짜를 설명하는 자료인지.
- `published_at`: 실제 발표 시각. 확인되지 않으면 추정 여부를 표시.
- `available_at`: 프로젝트 규칙상 사용할 수 있게 되는 시각.
- `retrieved_at`: 프로그램이 실제로 수집한 시각.
- `vintage_date`: 해당 통계 버전의 기준일.

과거에 알 수 없었던 최신 수정값을 과거 판단에 넣지 않는다. 과거 버전이나 시각이 부족하면 해당 구간을 엄밀한 시점 검증에서 제외하거나 보수적 지연을 적용한 제한적 연구로 표시한다. 자료가 없는 부분을 최신 데이터로 조용히 대체하지 않는다.

월별 값의 주간 유지와 새 발표를 구분한다. 예정된 발표가 없는 경우와 수집 실패도 구분한다. 과거 시장 예상치 자료가 없으면 전월 대비 개선을 “예상보다 좋았다”라고 표현하지 않는다.

### 3.3 가격 자료

미국 섹터 ETF와 SPY의 가격·배당·분할·거래일 자료는 별도 공급자 후보를 조사한다. 특정 무료 공급자를 아직 확정하지 않는다. 시제품 자료와 검증용 자료를 구분하고 표본 대조, 사용 조건, 배당 처리, 역사 범위, 비용을 확인한다.

ETF 실제 거래 가능 기간과 섹터 분류 변경을 반영한다. 현재의 11개 ETF를 출시 이전까지 연장하지 않는다. 장기 지수 연구와 실제 ETF 투자 검증을 구분한다. 모든 전략은 동일한 공통 검증 기간을 사용하고, 그 이전 자료는 별도 보조 분석으로 둔다.

## 4 점수 모델 명세와 착안 근거

### 4.1 무엇이 근거이고 무엇이 가설인가

| 요소 | 역할·착안 | 현재 상태 |
| --- | --- | --- |
| 경기와 섹터의 연결 | 매출·비용·할인율·신용 경로, 경기순환 투자 참고 [1] | 정성적 근거. 모든 시기에 같은 효과라는 보장은 없음. |
| 표준화 | 단위가 다른 지표를 과거 대비 상대 위치로 비교 | 일반적인 계산 방식. 수익률 예측력은 별도 검증. |
| 요인 가중합 | 여러 입력을 설명 가능한 한 숫자로 정리 | 자체 모델 구조. 인과효과 추정치가 아님. |
| 0~100 환산 | 읽기 쉬운 점수 척도 | 표시 방식. 확률·기대수익률이 아님. |
| 창 길이·제한값·계수 | 단순하고 재현 가능한 출발점 | 검증 전 실험값. 최적값으로 주장하지 않음. |

기존 점수표의 출처를 나중에 찾은 자료에 소급 귀속하지 않는다. 참고 문헌은 설계 원리와 한계를 설명하며, 정확한 섹터별 계수는 별도 근거서와 검증이 필요하다.

### 4.2 거시 요인 계산

시점 t에 이용 가능한 변환값을 x_i,t라 한다. 같은 기준 시점에 이용 가능한 과거 관측들 중 해당 최신 관측 이전의 값으로 평균 μ_i,t와 표준편차 σ_i,t를 계산한다.

`z_i,t = (x_i,t - μ_i,t) / σ_i,t`

`f_i,t = clip(z_i,t, -3, +3) / 3`

초기 창 후보는 월별 60개, 주별 260개, 일별 1,260개 유효 관측이다. 대략 5년이라는 설계 선택일 뿐 각 창의 통계적 동등성이나 최적성을 주장하지 않는다. 첫 버전은 필요한 관측 수를 확보하지 못하면 해당 요인을 보류한다. 전년 대비 변환을 위한 추가 원자료 기간도 확보한다.

표준편차는 표본 기준 `ddof=1`로 고정한다. 표준편차 0, 비유한 값, 단위 불일치는 보류 사유다. 월별 값을 매주 복제해 창 길이를 채우지 않는다. 새 값·수정치·유효성 변화가 없으면 같은 요인을 유지한다.

같은 축에 여러 지표가 있다면 먼저 각각 표준화하고 방향을 맞춘 뒤 단순 평균을 시작값으로 사용한다. 처음에는 축당 한 지표로 시작한다. 수준·변화·가속도를 전부 동시에 투입하지 않고, 추가 변환은 별도 실험으로 등록한다.

2026-10-10 후속 연구 메모: 사용자가 제안한 지표의 수준·변화 정도 병행 활용을 [R-001: 수준·변화·가속도 연구](research_backlog.md)에 등록했다. 현재도 증가율·기간 차이를 사용하므로, 기존 입력에 추가 정보가 있는지를 별도로 검증한다. M3 동결 모델은 유지하고 M4 기본 모델 평가 후 후속 후보로 검토한다. 상세 후보·위험·평가 절차는 해당 문서에서 관리한다.

### 4.3 섹터 점수

섹터 s의 요인 k에 대한 계수를 b_s,k, 요인값을 F_k,t라 한다.

`D_s = Σ_k |b_s,k|`

`기여도 C_s,k,t = 50 × b_s,k × F_k,t / D_s`

`점수 S_s,t = 50 + Σ_k C_s,k,t`

계수 후보는 -2, -1, 0, +1, +2이며 D_s=0이면 점수를 계산하지 않는다. 요인값이 -1~+1 안에 있으므로 점수도 0~100 범위다. 기준점 50과 기여도 합은 점수와 일치해야 한다.

**산식 설명용 가상 예시:** 성장 요인 +0.6, 금리 요인 +0.3이고 어떤 섹터의 계수를 각각 +2, -1로 가정하면 분모는 3이다. 성장 기여 +20점, 금리 기여 -5점이므로 최종 점수는 65점이다. 실제 섹터 계수나 관측 결과가 아니다.

모든 계수를 같은 배수로 키우면 정규화 때문에 점수는 그대로다. 따라서 이 계수는 상대적인 요인 비중을 나타내며, 섹터 수익률의 실제 민감도나 변동성을 나타내지 않는다. 65점은 상승 확률 65%도 기대수익률 6.5%도 아니다. 50점도 수익률 0의 기준이 아니다.

### 4.4 계수 근거서와 검증 순서

각 섹터·요인 조합에 `계수 / 영향 경로 / 참고 자료 / 반대 근거 / 적용 한계 / 작성일 / 모델 버전`을 기록한다. 정성적 근거만으로 크기를 정했다면 “정성 가설”이라고 표시한다. 근거 없는 칸을 AI가 임의로 채우지 않는다.

첫 실험의 전체 계수표는 검증 결과를 보기 전에 작성·동결한다. 현재 계획에는 검증된 계수표가 없다. 코드 실행 확인용 가상 계수와 실제 연구 가설용 계수를 분리한다. 전체 연구용 표를 완성하기 전 11개 섹터 연구 결과가 준비되었다고 주장하지 않는다.

동결 모델을 거시 정보가 없는 비교 전략과 평가한다. 훈련 구간에서 통계적으로 계수를 추정하는 모델은 그다음 별도 후보로 도입한다. 선택된 후보 수, 실패 결과, 변경 이유를 함께 기록한다. 여러 설정을 시도한 뒤 가장 좋은 결과만 고르면 과거 성과를 과장할 수 있다. [5]

### 4.5 누락 처리 변경

v1.0의 “80% 이상 관측 시 남은 가중치로 정규화”는 누락 자체가 점수 변화를 만들고 섹터 간 비교를 어렵게 할 수 있다. 따라서 첫 버전은 모델에 활성화한 모든 입력이 유효할 때만 비교 가능한 공식 순위를 계산한다. 처음부터 쓰지 않기로 정한 지표는 누락으로 세지 않는다.

정상 발표 주기 안에서 새 발표가 없으면 기존 값을 유지한다. 지표별 허용 지연을 넘기거나 핵심 입력을 확보하지 못하면 이번 주 순위·모의 리밸런싱을 보류하고 이전 보유를 유지한다. 이미 발생한 보유 손익은 계속 평가한다.

부분 점수는 진단용으로만 표시할 수 있으며 정상 점수와 직접 비교하지 않는다. 향후 80% 규칙을 도입하려면 별도 버전에서 누락에 따른 순위 왜곡을 검증한다.

상·하위 섹터 차이는 분석 지표이며 공매도 실행을 뜻하지 않는다. 기본 전략은 레버리지·공매도·현금 타이밍 없이 주식 섹터에 투자한다. 모든 섹터가 부진할 때의 원금 보호 전략으로 해석하지 않는다.

### 5.2 점수를 목표 비중으로 바꾸기

11개 섹터가 모두 유효한 공통 기간에 기본 비중은 각각 1/11이다. 점수 평균을 S̄라 할 때 시작값은 다음과 같다.

`u_s = 1/11 + 0.05 × (S_s - S̄) / 50`

`0.05`는 5%포인트라는 연구용 조정 강도다. 예를 들어 평균보다 10점 높으면 기본 비중에 1%포인트를 더한다. 목표 비중은 `합계 1, 각 섹터 0~0.20` 제약하에서 u와의 제곱거리 합이 가장 작도록 조정한다. 상한을 적용한 뒤 단순히 다시 나눠 상한을 깨는 방식은 쓰지 않는다.

소수 단위 보유가 가능한 연구 가정을 먼저 사용한다. 실제 최소 주문·잔여 현금 제약은 개인 투자 적용 전에 추가한다. 이 비중 규칙 역시 검증 전 가설이다.

### 5.3 비교할 세 가지 거래 빈도

| 실험 | 판단·거래 규칙 | 목적 |
| --- | --- | --- |
| W: 매주 조정 | 매주 유효한 목표 비중으로 조정. 목표와 현재 비중이 같으면 거래 없음. | 빠른 반영 효과 측정 |
| M: 매월 조정 | 매월 첫 미국 거래일에, 그 체결 전에 확정된 가장 최근 주간 점수로 조정 | 기존 계획의 월간 기준과 비교 |
| C: 조건부 주간 조정 | 매주 검토하되 아래 비중 이탈 기준을 넘을 때만 조정 | 반응 속도와 거래량을 함께 관리하는 주실험 후보 |

조건부 규칙의 초기 후보는 `max_s |목표 비중_s - 현재 비중_s| ≥ 0.02`이다. 즉 어느 한 섹터라도 2%포인트 이상 차이가 나면 전체 목표 비중으로 조정하고, 그렇지 않으면 보유를 유지한다. 비교 시 현재 비중에는 그동안의 가격 변화와 배당·현금을 반영한다. 순위 변화만으로 거래하지 않는다.

2%포인트는 검증 전 시작값이다. 주실험으로 C를 먼저 등록하고 W·M을 비교군으로 두되, 최종 채택은 비용 반영 검증 뒤 판단한다. 검증 전 제한된 후보만 정하고 최종 평가 결과를 본 뒤 가장 좋은 주기를 사후 선택하지 않는다. 데이터가 부족하면 거래 빈도 우열은 보류한다.

동일 비중 비교 전략에도 대응하는 일정·이탈 규칙을 적용한다. SPY는 매수 후 보유 기준이다. 단순 가격 추세 비교 모델은 예를 들어 지난 12개월 중 최근 1개월을 제외한 총수익률로 상위 3개를 동일 비중 보유하는 규칙을 훈련 전에 고정할 수 있다. 이 추세 전략은 집중도가 다르므로 그 차이를 거시 정보의 효과로 단정하지 않는다.

연구용 기본 체결은 판단 후 처음 도래하는 미국 정규장의 종가로 둔다. 늦게 실행되어 그 시점을 놓친 경우 과거 가격으로 체결했다고 기록하지 않는다. 실시간 모의 운용에서는 실제 계산 완료 후 가능한 다음 체결 시점으로 넘긴다. 종가 체결은 수수료·스프레드·미끄러짐을 별도로 반영하는 근사이며, 실제 주문 체결 보장이 아니다.

가격 자료는 비조정 가격·배당·분할로 원장을 만드는 방법과 검증된 총수익률 계열을 사용하는 방법 중 하나로 일관되게 선택한다. 조정가격에 배당을 다시 더하지 않는다. 비용은 매수·매도 각각의 실제 거래대금에 적용한다.

초기 비용 민감도 예시는 거래대금당 편도 5/10/25bp다. 1bp는 0.01%이며, 이 값은 실제 증권사 요금의 인용이 아닌 연구 가정이다. 총 매수·매도액 합계를 기준으로 비용을 계산하고, 회전율을 그 절반으로 정의한다면 지표와 비용 산식의 차이를 명시한다. 거래비용 차감·개인 세금 반영 전 달러 성과를 기본으로 표시한다. 원화 환산·환전 비용·개인 세금 반영은 개인화 단계에서 다룬다.

### 5.5 과거 검증의 순서

1. 자료의 공통 가용 기간과 표준화 준비 기간을 확인한다.
2. 개발·검증·최종 평가 구간을 시간순으로 분리한다. 실제 날짜와 합격 기준은 결과를 보기 전에 실험 설정에 기록한다.
3. 앞선 자료로만 규칙을 정하고 이후 구간을 평가한다. 3개월 성과가 아직 확정되지 않은 훈련 사례는 제외한다. 구간 경계에서도 성과 측정 종료일이 경계를 넘는 사례를 차단한다.
4. 같은 데이터·가격·비용 조건으로 W/M/C와 비교 전략을 실행한다.
5. 겹치는 주간 3개월 성과를 독립 사례로 세지 않는다. 시간 의존성을 고려한 블록 재표본화 등으로 불확실성을 추정한다.
6. 최종 평가 후 규칙을 변경했다면 해당 기간은 더 이상 독립적인 최종 평가 기간이 아니다. 새 버전과 새로운 미래 기록으로 확인한다.
7. 실제 주간 모의 운용에서 데이터 지연·재실행·판단 이력을 확인한다.

판정은 “추가 검증을 진행할 근거 있음 / 자료 부족으로 보류 / 수정 필요”로 남긴다. 특정 시기·섹터에 성과가 몰리는지, 비용 변화에 결론이 뒤집히는지 함께 제시한다. 짧은 모의 운용으로 장기 우위를 입증했다고 표현하지 않는다.

## 6 최소 위험 검증과 보고서 연동

### 6.1 최소 검증과 후속 기능의 경계

| 항목 | 초기 포함 여부 | 확인할 질문 |
| --- | --- | --- |
| 실제 충격기를 포함한 전체 성과 | 포함 | 불리했던 기간을 제외해야만 성과가 좋은가? |
| 최대 낙폭·회복기간 | 포함 | 손실 규모와 회복에 걸린 시간은 어느 정도인가? |
| 비용 확대·한 거래일 체결 지연 | 포함 | 작은 실행 조건 변화로 성과가 사라지는가? |
| 자료 누락·수집 지연 | 포함 | 정상 점수로 가장하거나 잘못 거래하지 않는가? |
| 계수·표준화 설정의 소수 대안 | 검증 단계 포함 | 특정 설정 하나에만 결과가 의존하는가? |
| 가상 거시 충격→가격 손실 변환 | 후속 | 검증된 별도 수익률·위험 모델이 있는가? |
| 상관관계 급변·유동성 위기 시뮬레이션 | 후속 | 개인 포트폴리오 단계에서 필요한가? |

과거 충격 구간은 외부 사건 기준 등 결과에 독립적인 정의로 기록하며, 전체 성과에서 삭제하지 않는다. 초기 ETF 공통 기간 밖의 사건은 검증 범위를 벗어난다고 표시한다. 사후에 안 사건 날짜를 당시 매매 신호로 사용하지 않는다.

점수 모델만으로 “금리 1%포인트 상승 시 포트폴리오가 몇 % 손실”이라고 계산할 수 없다. 점수와 수익률의 검증된 연결이 없기 때문이다. 충격에 따른 점수 변화 실험과 손실 추정 실험을 구분한다.

### 6.2 보고서의 기본 구성

1. 이번 주 핵심 판단: 환경, 가장 큰 변화, 유지·변경된 판단.
2. 새 데이터: 발표·수정·미발표·지연을 구분.
3. 거시 요인: 원래 값, 변환값, 표준화값과 방향.
4. 섹터 비교표: 점수·순위·전주 차이·4주 및 13주 변화·요인 기여도.
5. 판단 이력: 이전 판단, 현재 판단, 바뀐 조건, 아직 유지하는 반대 근거.
6. 모의 운용: 현재·목표 비중, 거래 여부, 거래하지 않은 이유, 비용.
7. 검증 결과: 만기 도래 전망·점수의 후속 성과, 전략별 결과.
8. 다음 확인 사항과 부록: 확인 가능한 공식 발표 일정, 출처, 버전, 한계.

기본 출력은 짧은 요약과 상세 부록을 가진 Markdown·HTML이다. 처음부터 PDF 생성은 필수가 아니다. 최소 그래프는 점수 추이·기여도·전략별 누적 성과·낙폭으로 한다.

### 6.3 비교표와 추세 규칙

각 섹터에 이번 점수, 전주 점수, 점수 차이, 현재·이전 순위, 4주 전·13주 전 대비 차이, 주요 기여 요인, 모델 버전, 자료 상태를 표시한다. 아래는 형식 설명용 가상 예시다.

| 섹터 | 전주 | 이번 주 | 차이 | 순위 변화 | 변화 원인 |
| --- | ---: | ---: | ---: | --- | --- |
| 예시 A | 61 | 65 | +4점 | 5위 → 3위 | 성장 +3점, 금리 +1점 |

주차는 한국시간 기준 주간 슬롯으로 연결한다. 전주 기록이 없으면 “전주 비교 없음”으로 표시하고 마지막 보고서 날짜와 별도 비교한다. 4주·13주 이력이 없으면 가용 기간을 명시한다. 정정판을 포함해 같은 주의 여러 실행을 여러 주로 세지 않는다.

점수 차이는 “점”으로, 수익률·비중 차이는 “%포인트”로 표기한다. 순위 개선은 `이전 순위 - 현재 순위`로 정의한다. 동점 순위 처리 규칙을 고정한다. 연속 상승은 0보다 큰 주간 변화가 몇 번 이어졌는지 계산하며, 미발표에 따른 동일 값 반복을 개선으로 세지 않는다. 점수 상승과 다른 섹터 하락에 따른 순위 상승도 구분한다.

### 6.4 변화 원인 분해

모델·입력 범위가 같은 두 보고서에서는 요인별 기여도 차이의 합이 전체 점수 차이와 같아야 한다. 다음 원인을 별도로 기록한다.

- 새 관측 발표: 새 달·주·일 자료의 유입.
- 과거 통계 수정: 같은 관측 대상에 대한 값의 변경.
- 기준창 이동: 표준화 평균·표준편차가 달라진 효과.
- 모델 변경: 변환·계수·지표 구성·누락 처리 변경.
- 자료 상태 변경: 지연·복구·누락에 따른 비교 가능성 변화.

원인에 상호작용이 있을 수 있어 분해 순서를 고정한다. 같은 모델에서는 “이전 상태 → 과거 수정 반영 → 새 관측 반영 → 기준창 갱신” 순으로 중간 점수를 계산하고 각 차이를 기록한다. 새 관측 반영 단계에서는 기존 표준화 기준을 잠시 고정해 비교한다. 중간값은 원인 설명용 재계산이며 당시 실제 발표 점수가 아니다. 순서에 따라 기여량이 달라질 수 있으므로 인과효과로 해석하지 않는다.

모델이 바뀌면 구모델의 지난주·이번 주 점수와 신모델의 이번 주 점수를 함께 계산할 수 있을 때 경제 입력 효과와 모델 변경 효과를 나눈다. 재계산할 자료가 없거나 입력 유효성이 다르면 수치를 억지로 분해하지 않고 비교 불가 사유를 표시한다. 원래 보고서는 유지하고 재계산 이력은 별도로 저장한다.

### 6.5 과거 판단의 성과 평가

`forecast_id`, 판단 시점, 대상, 기간, 평가 만기, 당시 근거, 판단 변경 조건을 저장한다. 3개월 평가 만기 전에는 중간 경과로만 표시한다. 경제 전망의 채점 기준도 최초 발표값인지 이후 수정값인지 미리 정한다. 초기 기본안은 최초 발표값으로 채점하고 이후 수정값 평가는 별도로 둔다.

당시 판단과 현재 판단을 함께 보존한다. 최신 자료로 과거 보고서를 다시 쓴 결과를 당시 예측의 성공으로 계산하지 않는다. 비교 보고서는 AI 없이 생성할 수 있어야 한다.

## 7 저장소·자동 실행·비용 관리

| 경로 | 역할 |
| --- | --- |
| `.devcontainer/devcontainer.json` | 개발 환경 |
| `pyproject.toml`, `uv.lock` | 버전·의존성 |
| `config/indicators.yaml` | 지표·변환·빈도·이용 시점·지연 규칙 |
| `config/sectors.yaml` | 계수·계수 근거 참조·버전 |
| `config/evaluation.yaml` | 기간·W/M/C·비용·체결·평가 규칙 |
| `src/macro_sector/` | 수집·시점·계산·이력·검증·보고서 |
| `templates/`, `tests/` | 보고서와 핵심 검증 |
| `docs/model_card.md` | 경제적 가설·반대 근거·한계 |
| `docs/experiments.md` | 시도·실패·선택 이유 |
| `docs/prompts/` | 단계별 코드 제작 프롬프트 |
| `.github/workflows/` | 코드 검사와 주간 실행 |

명령 인터페이스 설계안: `ingest`, `score --as-of`, `compare --run-id --previous-run-id`, `backtest --config`, `report --run-id`, `weekly`. 구현·설치 전에는 실행 가능한 명령으로 안내하지 않는다.

Codespaces는 개발·수동 실행, Actions는 정기 실행 후보로 둔다. 정기 실행 전에 장기 저장소와 복구 방법을 선정한다. 데이터 사용 조건이 허용하는 범위에서 비공개 저장하고, 코드는 Git으로 관리한다. API 키는 환경변수·Secrets에 두고 로그에 남기지 않는다.

주간 작업은 원본 수집, 품질 검사, 점수 계산, 이전 기록 비교, 만기 평가, 보고서 생성, 영구 저장 순이다. 중간 실패·중복 실행·예약 지연·수동 재실행을 처리한다. 외부 전달 채널은 별도 요청 시 연결한다. 이번 문서 개정은 예약 작업이나 전송 설정을 생성하는 작업이 아니다.

초기 추가 지출 목표는 0원이다. 무료 범위가 부족하면 먼저 수동 실행·실행 횟수·저장 범위를 조정한다. 유료 우선순위는 검증을 막는 가격·과거 데이터 품질, 안정적 저장·운영, 편의 기능 순으로 제안한다. 추가 AI 설명을 최우선 구매 항목으로 두지 않는다.

유료 전환의 판단 자료는 데이터 공백, 실제 운영비, 검증 결과, 사용자가 얻는 편익이다. 월 추가 예산 1만~2만 원 안에서 해결되지 않는 데이터 문제가 있으면 검증 범위를 축소하고 한계를 남긴다. 예산이 허용된다고 먼저 결제하거나 유료 API를 기본값으로 켜지 않는다.

## 8 개발 단계와 완료 기준

| 단계 | 작업 | 종료점 |
| --- | --- | --- |
| 1 작은 동작 버전 | 환경 확인, 네 지표, 가상 계수 계산, 템플릿 | 한 명령으로 JSON·Markdown 생성. 샘플과 실제 자료 구분. |
| 2 이력·시점 기반 | 원본 버전, 이용 가능 시점, 실행 기록, 전주 비교 | 과거 입력 재현과 두 실행의 차이 추적 가능. |
| 3 연구용 점수 | 계수 근거서, 전체 계수 동결, 11개 섹터 | 점수·기여도 일치와 누락 보류 동작. |
| 4 과거 검증 | 가격 검증, 비교 전략, W/M/C, 최소 위험 점검 | 미래 정보 없는 비용 반영 결과와 불확실성 보고. |
| 5 보고서 완성 | 4주·13주 추세, 원인 분해, 과거 판단 평가 | 저장 결과에서 재생성하고 변화 합계를 설명. |
| 6 자동 운영 | 영구 저장·복구·주간 실행 | 중복·지연·중간 실패를 처리. |
| 7 실시간 모의 운용 | 고정 모델의 새로운 주간 기록 | 운영 안정성과 예측 결과를 구분해 누적. |
| 8 확장 판단 | 증거와 비용 검토 | 유지·수정·보류, 필요 시 유료 데이터·대시보드 추가. |

달력상의 완료일은 아직 정하지 않는다. 데이터 확보 상태에 따라 검증 단계가 길어질 수 있다. 초기 이력 비교 기능을 앞당겨 개발 초기부터 매주 무엇이 바뀌었는지 확인할 수 있게 한다.

중요 테스트: 미래 발표·수정치 차단, 표준화 경계·표준편차 0, 점수와 기여도 합, 변화 분해 합, 비중 합·상한, 손계산 가능한 거래·배당·비용 예제, 휴장·체결 지연, 누락 보류, 재현·중복 방지.

프로그램이 정확히 실행되는 것과 투자에 도움이 되는 것은 별도 완료 조건이다. 초기 점수에는 “미검증 연구용”을 표시한다.

## 9 코드 제작 프롬프트와 협업 방식

사용자는 간단한 코드를 작성할 수 있다는 전제로 설명하되 Python 고유 문법과 파일 구조를 짧게 안내한다. 각 단계마다 목적, 바꿀 파일, 실행 명령, 정상 출력, 오류 확인 방법을 제공한다. 기존 저장소·환경이 있으면 확인 후 이어서 사용한다.

아래는 첫 구현 요청에 재사용할 수 있는 프롬프트다. 아직 이 프롬프트가 실행되었거나 프로그램이 작성된 것은 아니다.

> 첨부한 MacroLens 계획 v2.0을 기준으로 개발 단계 1만 구현해줘. 먼저 현재 저장소와 실행 환경을 확인하고 기존 코드가 있으면 이어서 작업해줘. Python 경험이 제한적이므로 파일별 역할과 실행 방법을 설명해줘. 네 거시지표의 출처·관측일·이용 가능 시점·수집 시각을 기록하고, 실행 확인용 가상 계수와 실제 연구용 계수를 분리해줘. 샘플 자료는 실제 API 자료처럼 표시하지 말고 JSON과 한국어 Markdown 보고서에 미검증 표시를 넣어줘. 추가 유료 서비스와 AI API는 사용하지 않아도 동작하게 해줘. API 키는 대화에 요청하지 말고 환경변수 설정 방법을 안내해줘. 계산·누락 처리의 중요한 테스트를 실행하고 실제 성공 여부를 보고해줘. 완료 후 실행 명령, 정상 결과 예시, 다음 단계에서 구현할 항목을 설명해줘.

후속 프롬프트는 한 번에 한 단계의 목적·입력·출력·완료 조건을 담는다. 실패한 테스트를 숨기거나 실행하지 않은 결과를 완료로 표현하지 않는다.

## 10 남아 있는 결정과 현재 상태

미국 한정·개발 경험·예산은 이번 답변으로 반영했으므로 반복 질문하지 않는다. 다음 구현 시 필요한 것은 기존 GitHub 저장소·Codespace·파일 접근 여부 확인이다.

검증 전에 확정할 것: 계수 근거서, 가격 공급자, 실제 검증 기간, 합격 기준, 비용 가정. 자동화 전에 확정할 것: 저장처·복구·발행 일정. 개인화 전에 확인할 것: 투자 기간, 위험 한도, 기존 자산, 환율·세금 기준.

현재 완료: 계획 개정과 설명, 맥락 파일의 조건 정합성 수정. 미완료: 실제 프로그램 구현, 데이터 수집·계수 검증·백테스트·예약 실행·모의 운용. 이 문서의 숫자 예시는 실험 결과가 아니다.

첨부 맥락 파일과 이 계획이 충돌하면 최신 사용자 지시를 우선한다. 함께 제공하는 맥락 v2.0은 이번 계획을 참조한다.

## 11 참고 자료와 적용 범위

아래 자료는 2026-10-01 확인했다. 기술 패키지 가격·무료 한도·최신 지원 버전은 이 문서에서 확정하지 않으며 구현 시 확인한다.

1. [Fidelity — How to invest using the business cycle](https://www.fidelity.com/viewpoints/investing-ideas/sector-investing-business-cycle). 경기와 섹터 성과를 연결하는 관점의 참고. 본 프로젝트의 점수 산식·계수 출처는 아님.
2. [Investor.gov — Rebalancing](https://www.investor.gov/introduction-investing/investing-basics/glossary/rebalancing). 가격 차이로 보유 비중이 달라질 수 있다는 설명. 주간·월간 우열이나 2%포인트 기준을 뒷받침하지 않음.
3. [Federal Reserve — 2026 hypothetical stress test scenarios](https://www.federalreserve.gov/newsevents/pressreleases/bcreg20260204a.htm). 가상 시나리오와 예측의 구분. 은행용 시나리오를 그대로 적용하지 않음.
4. [FRED API — Real-Time Periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html). 당시 알려진 자료와 수정된 자료의 구분에 참고.
5. [Bailey 외 — The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf). 반복적인 전략 탐색과 과거 성과 과장의 문제. 이 논문의 특정 절차를 이미 구현했다는 뜻은 아님.

## 12 v1.0 → v2.0 변경 이력

- 미국을 잠정 대상에서 확정 범위로 변경.
- 개발 경험을 “간단한 코드 작성 가능, Python은 제한적”으로 구체화하고 코드 제작 프롬프트 추가.
- 비용을 기존 ChatGPT 고정 비용과 효과 확인 후 월 추가 1만~2만 원으로 구분.
- AI 개발 지원과 프로그램 내 선택적 AI 설명을 분리.
- 점수 산식의 자체 가설 성격, 표준화 방향, 계수 정규화의 한계를 명시.
- 불완전 입력의 공식 순위 산출을 보류하도록 누락 처리 단순화.
- 월간 거래 단일안에서 W/M/C 비교와 조건부 주간 주실험 후보로 변경.
- 복잡한 스트레스 시뮬레이션을 후속 단계로 이동.
- 이전 보고서 연결·추세·변화 원인 분해·모델 변경 구분을 핵심 기능으로 추가.
- 이력 비교를 개발 초기에 배치하고 구현 여부·실험값·확정 사항을 구분.
